# Nova Audit + Wave One MVP — Acceptance Matrix

Source: Isaac Nova's "MASTER EXECUTION PROMPT — NOVA AUDIT AND WAVE ONE WORKING MVP" and
"MASTER EXECUTION PROMPT — MAKE NOVA WORK END TO END" (2026-09-29). Both pause hierarchy/Venture
Lab/autonomous-executive/marketing-redesign work in favor of one connected, usable MVP: secure
login → business intake → Nova Audit → reviewed/approved report → approved proposal → client
acceptance → installation → operation → measurement → improvement.

This is step 1 of that prompt ("INSPECT ONCE AND ESTABLISH THE BASELINE"), built from four
parallel codebase surveys (Nova Audit journey, Wave One systems, Installations/Proposals/
Payments/Dashboards, Auth/Security/Isolation) plus direct reads of `api/_twilio.js`,
`api/_auditResearch.js`, git state, and the Vercel function count. Agent claims were verified
against file:line citations, not taken as ground truth; prior status docs (`docs/PRODUCT_BUILD_STATE.md`,
`docs/requirement-matrix.md`, `docs/NOVA_PILOT_ACCEPTANCE_RESULTS.md`) were treated as claims to
re-check, not facts.

**Status vocabulary for this document (per the MVP master prompt — narrower than CLAUDE.md's
8-term vocabulary):** Not built / Built / Locally tested / Staging verified / Production verified.
Nothing in this matrix is "Production verified" — no migration in this phase has been applied to
Supabase, no code has been pushed or deployed. Git state: local `main` is 2 commits ahead of
`origin/main` (unpushed), plus a large uncommitted working tree from the paused hierarchy phase.

**Two naming collisions this document deliberately does not conflate:**
- **"Wave One" (A)** — the real lead-capture/call/SMS/booking product (`api/_wave1*.js`, dashboard
  page `PilotConsole.jsx`). **"Wave One" (B)** — Nova's own sales-funnel cohort-application form
  (`Waves.jsx`/`WavesForm.jsx`/`api/waves-intake.js`, dashboard page `WaveOne.jsx`). The master
  prompt's "Wave One systems" means (A).
- **`/dashboard/jobs`** (`Jobs.jsx`) is the hiring/ATS applicant tracker — **not** the durable
  background-job-queue `jobs` DB table used by `worker/index.mjs`/`claim_next_job()`.
- Two disconnected audit-intake systems: `businesses`/`audit_cases` (the real, tested audit
  engine) vs. `intake_submissions`/`nova_ai_audits` (a separate `Intake.jsx` flow). No code
  bridges them today — see Gap A-1 below.
