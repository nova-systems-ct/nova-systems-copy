# Nova launch — Tuesday, November 10, 2026

## Customer-facing release

The homepage and booking experience use the approved black, white and gold palette. The existing supplied hero video remains unchanged. Navigation, footer and the assistant button point to the actual request-and-booking worker. The old first-visit marketing popup stays removed. A live acceptance check found and corrected a one-time new-request flag that cleared the receipt on reload; that URL path is now covered by the real browser regression.

The public worker at https://nova-systems.app/service-request saves the service request, reuses or creates the existing CRM contact, records the exact optional service-SMS choice, reserves a published Nova phone appointment when selected, and creates a real follow-up task. All database writes commit together or roll back. A completion receipt reports actual actions, including whether an appointment remains pending. Booked customers can download a calendar file and cancel from the same browser session. Calendar files are downloads, not emailed invitations or Google synchronization.

This is a deterministic workflow worker. It does not dispatch a language model, SMS, email, phone call or payment. Creating a task is not completion of the owner's follow-up work.

## Owner setup before accepting appointments

1. Sign in to https://nova-systems.app/login with the existing Nova owner account.
2. Open https://nova-systems.app/dashboard/intake-forms.
3. In **Nova Launch Desk**, enter real start/end times you can attend. Inputs explicitly use Eastern time. Leave **Test appointment only** unchecked for customer availability.
4. Publish each available phone appointment. Overlapping times are rejected; already-booked slots cannot be silently withdrawn.
5. Open the public assistant in a separate browser and verify your times. Requests without appointments still create real follow-up tasks.
6. Review the saved request, contact details, appointment and next task in the launch desk. You must actually make the call and handle the follow-up task.

No real owner availability has been invented or published. A separate synthetic test appointment is excluded from the live customer calendar. Test workspace: https://nova-systems.app/service-request?test=1&new=1. It requires an `@example.invalid` email and a reserved `555-01xx` phone number; it must never be used as proof of a real customer or real telephone conversation.

Cancellation controls are held in the same browser tab's session storage. A calendar download does not include the cancellation credential. Customers who lose their browser session can contact Nova for changes; the authenticated owner can cancel the saved request from Launch Desk without receiving the customer’s management secret. Email ownership verification and external calendar conflict detection are not implemented in this release.

## Production database

Applied migrations `20261109194341_launch_worker_booking.sql` and `20261109195329_launch_worker_owner_cancel.sql` to the existing production database. Both new tables have RLS enabled, no public/authenticated grants and no customer-readable policies. All four RPCs are SECURITY INVOKER with an empty search path and EXECUTE granted only to the server service role. Owner RPC independently verifies active `nova_super_admin` membership in the active Nova internal organization. Public requests cannot choose an organization or supply an actor.

The post-migration security advisor has the same pre-existing warning categories/counts as before this release. The two additional informational RLS-without-policy notices are intentional for private server-only tables. Existing warning categories include mutable function search path, legacy executable security-definer functions and leaked-password protection; they are not introduced by this migration. Guidance: https://supabase.com/docs/guides/database/database-linter

No additional Vercel public function was created: public actions use `/api/book-meeting`; authenticated owner actions use `/api/client?resource=launch`.
